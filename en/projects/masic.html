Flagship Project

MASIC

MASIC is my flagship engineering project: a complete computer architecture designed from scratch for educational purposes, with an original ISA, a microprogrammed control unit and working 74HC-based hardware. It spans the instruction set architecture, processor microarchitecture, memory organization and software toolchain.

The project emphasizes engineering clarity, architectural consistency, and hardware/software co-design. Rather than relying on programmable logic, the implementation uses discrete 74HC-series logic integrated circuits to expose the hardware structure directly at the system level.

Overview

MASIC was conceived as a complete computer system that can be understood from the ground up. Its architecture includes an original 8-bit accumulator-based CPU, a custom 16-bit address space, a hardwired control unit, a 64 KiB main memory, an independent 64 KiB I/O space, nested interrupts, multiple addressing modes, a complete stack architecture, and a software environment designed specifically for the machine.

The design philosophy is not to build a practical production machine, but to make every architectural decision explicit and teachable. This makes MASIC both a technical achievement and an educational instrument for understanding how computers are structured at the hardware and software boundary.

CPU

The central processing unit is the heart of MASIC. It is an original accumulator-based architecture designed around simplicity and consistency. The CPU includes a microprogrammed control unit, a 16-bit program counter, a 16-bit stack pointer, a rich set of addressing modes, and a custom instruction set tailored to the machine's educational goals.

The instruction encoding was designed to remain regular and understandable, while still supporting the essential operations required for a functioning computer system. The memory model includes little-endian organization, a complete stack model, and an interrupt system with a peripheral-supplied interrupt vector.

The architecture also includes support for subroutines and interrupts through a stack-based runtime model, making the CPU capable of handling structured control flow rather than only simple instruction sequencing. The hardware has been built and works as a real system.

Video Display Adapter

The video display adapter is an independent hardware subsystem created specifically for MASIC. Instead of integrating the display hardware directly into the CPU board, the project separates computation from display generation, which results in a cleaner and more realistic modular system structure.

The subsystem was implemented using 74HC-series logic integrated circuits and required the design of digital video generation logic, timing circuitry, memory interface logic, synchronization mechanisms, and system integration. The board acts as a dedicated peripheral that communicates with the CPU through a custom hardware interface.

This separation makes the project more representative of real computer systems, where independent devices interact through well-defined interfaces rather than sharing the same physical logic fabric.

Assembler

MASIC includes a custom assembler designed to support the architecture's instruction set and programming model. The assembler provides symbolic labels, an expression evaluator, and a macro system with support for nested and parameterized macros.

The purpose of the assembler is not simply to translate code but to make the machine accessible as a programmable system. Its design reflects the same educational philosophy as the hardware: every stage of translation should be understandable and consistent with the underlying architecture.

The assembler also supports relocation features and clear documentation so that software and hardware can be developed together as a coherent system rather than as separate domains.

Emulator

The software emulator provides a way to execute MASIC programs in a controlled environment without requiring the physical hardware to be present. It was developed as a companion tool to the assembler and the hardware architecture, allowing software development and architectural validation to proceed in parallel.

The emulator makes it possible to test instruction behavior, debug software concepts, and reason about the runtime semantics of the machine. Its role is central to the project's educational value because it bridges the gap between hardware design and software execution.

This toolchain approach demonstrates complete hardware/software co-design: the architecture, assembler, emulator, and hardware implementation are all part of a single coherent engineering story.

Engineering Notes

The project was intentionally designed to make architectural decisions visible rather than hidden behind abstraction layers. This decision affects every subsystem, from the CPU to the assembler and emulator, and reflects a strong commitment to understanding the machine as an integrated system.
